⚡ Skills (commandes /)

✅
Les skills s'invoquent avec /nom-du-skill dans le chat. Ceux marqués caveman réduisent la consommation de tokens d'environ 75%.

Skills projet (custom)

🔍

feature

/feature <nom>

Spawne 2 subagents Haiku en parallèle : un lit les fichiers mobile (page, style, service), l'autre lit le backend (service, controller, DTOs). Retourne un état des lieux des deux côtés avec les incohérences.

🔄

sync-types

/sync-types

Compare types/index.ts mobile avec le schéma Prisma et les DTOs NestJS. Affiche un tableau Markdown par entité avec le statut de chaque champ (✅ ok / ⚠️ manquant / ❌ incompatible).

Skills Caveman (économie de tokens)

🗿

caveman

/caveman

Active le mode communication ultra-compressé. Niveaux : lite, full (défaut), ultra. Coupe ~75% des tokens. Désactiver avec "stop caveman".

📝

caveman-commit

/caveman-commit

Génère des messages de commit Conventional Commits ultra-courts. Sujet ≤ 50 chars, body uniquement si le "pourquoi" n'est pas évident.

👁️

caveman-review

/caveman-review

Code review ultra-compressé. Un commentaire = une ligne : localisation + problème + fix. Zéro bruit.

🗜️

caveman-compress

/caveman-compress <fichier>

Compresse un fichier mémoire (CLAUDE.md, todos) en format caveman pour réduire les tokens d'entrée. Sauvegarde un backup .original.md.

👥

cavecrew

/cavecrew

Guide de délégation aux subagents caveman. Décide quand spawner investigator (localiser du code), builder (éditer 1-2 fichiers) ou reviewer (relire un diff). Output compressé à ~60%.

📊

caveman-stats

/caveman-stats

Affiche la consommation réelle de tokens de la session et les économies estimées. Lit directement les logs de session Claude Code.

🔄 Workflow recommandé

Pour chaque nouvelle feature full-stack :

1

Lancer /feature

Tape /feature <nom> pour avoir un état des lieux complet des deux côtés (mobile + backend) avant de toucher au code.

2

Backend d'abord (agent nestjs)

Modifie le service/controller backend. L'agent vérifie tsc --noEmit après chaque changement.

3

Vérifier /sync-types

Lance /sync-types pour s'assurer que les types mobile sont alignés avec les nouveaux DTOs backend.

4

Mobile ensuite (agent react-native)

Implémente l'écran/composant mobile. L'agent demande un mockup ASCII en premier pour les nouveaux écrans.

5

Commit avec caveman-commit

L'agent demande confirmation. Utilise /caveman-commit pour un message de commit propre et concis.

📋 Règles globales de tous les agents

🚫

Jamais sans confirmation

  • Aucun git commit sans validation explicite
  • Aucun git push sans validation explicite
  • Le diff est toujours affiché avant de demander
✅

Vérification TypeScript

  • npx tsc --noEmit après chaque modification
  • Zéro erreur TS avant de continuer
  • Si erreur → corrige d'abord, code après
💰

Économie de tokens

  • Haiku pour lecture de fichiers (subagents)
  • Sonnet pour code et analyse
  • Opus uniquement pour la sécurité
  • Style caveman dans tous les agents
